## 🎯 Elevator pitch

- **Question.** Can an agent with vision + sonar learn to operate by sonar in an arena it has only *seen*, not *pinged*?
- **Claim.** Yes — by (a) learning a generic sonar-interpretation model from vision-supervised data, (b) using that model as a simulator to mentally rehearse, (c) cloning a teacher policy inside that simulator. No on-robot training in the target arena.
- **Empirical test.** Matched vs. cross-arena swap. Matched > swapped ⇒ the policy uses *arena-specific structure*, not generic dead-reckoning.
- **Backup test.** Blind ablation. Stripping sonar from the policy input should break it under motor-noise injection.

## 🧠 Theoretical framework

> Framework = the broader claim. Paper instantiates a slice of it. State the full thing so the proposal can cite it later.

### Core concepts

- **F** = features *in the world*. Objective. The agent never touches them directly.
- **F̂** = features *in the agent*. Internal estimate. This is what perception produces and what action consumes.
- **filter_M** = world's physics for modality M. Maps F → data_M. NOT a model the agent owns.
- **inverse_M** = agent's perceptual model. data_M → F̂.
- **forward_M** = agent's generative model. F̂ → predicted data_M.

> Conflating **F** and **F̂** papers over the inversion problem. Keep them apart.

### Per-modality structure

Every modality M (vision, sonar, smell, …) has the same five-box structure:

```
F → filter_M → data_M → inverse_M → F̂_M
                                      ↓
                                forward_M → predicted_data_M
```

### Multi-modal: F_V ≠ F_S

- **Different filters preserve different features.**
- F_V (vision-accessible) ∩ F_S (sonar-accessible) ≠ ∅, but neither contains the other.
- Vision-only: color, lighting, distant landmarks.
- Sonar-only: occluded-reflective geometry, material acoustic properties.
- **Overlap: layout / close-range wall geometry.** ← this is where cross-modal calibration lives.

### Question hierarchy

| # | Question | Type |
|---|---|---|
| **Q1** | What can each modality, in principle, recover from data_M? | info-theoretic |
| **Q2a** | Can B supervise A's inverse model in the overlap? | learning |
| **Q2b** | Can A's forward model be learned? From what F̂_true? | learning |
| **Q2c** | Can the learned forward_A *replace* data_A for downstream learning (e.g. a policy)? | learning + use |

### Q1 — Encoding (info-theoretic)

Three regimes per (feature, filter) pair:

- **Preserved.** Naive inverse exists. e.g. *vision/color*.
- **Lossy.** Info survives but mixed/noised. Learned inverse can extract; naive cannot. e.g. *sonar/distance*.
- **Destroyed.** Many-to-one collapse. No inverse possible, period. e.g. *sonar/color*.

> Q1 partitions features per modality. **f ∈ F_M iff filter_M is preserved-or-lossy for f.** The Venn structure of F_V vs F_S is generated by this partition.

### Q2a — Cross-modal inverse training

> If f is lossy under filter_A but accessible under filter_B, can B-labels train inverse_A?

- **Necessary condition.** f ∈ F_A AND f ∈ F_B. If A destroys f, B cannot rescue it.
- **Asymmetry.** B used at training only. At deploy, only A is available.
- **Data requirement.** Paired `(data_A, F̂_B)` collected simultaneously.

### Q2b — Forward model learning

- **(i)** forward_A can be learned from `(F̂_true, data_A)` pairs. Crux: source of F̂_true.
- **(ii)** Bootstrap: once forward + inverse exist, prediction error can refine F̂. (Classic predictive coding.)

### Q2c — Vicarious rehearsal

> Given trained forward_A and any source of F̂, the agent can generate downstream training experience *without ever invoking filter_A*.

- The **use** of the forward model is the contribution, not just its existence.
- Specialised to policy learning: behavioural cloning of a teacher, using simulated sensory experience.

### The figure (`theory.drawio`)

Three colored learning regimes overlaid on the structure:

| color | learns | corresponds to |
|---|---|---|
| 🟢 green | `inverse_M1` | Q2a |
| 🟡 yellow | `forward_M1` | Q2b |
| 🔵 blue | the **policy** (F̂_M1 → Action) via BC | Q2c, specialised |

- **Mental representation** = teacher with `(state, desired action)` output. Not generic imagination.
- **Uncoloured edges** = the standard sense → act path that runs at deployment, after all training has finished.
- **All coloured edges fall silent at deployment.** Caption-worthy.

## 📋 What this paper instantiates

### ✅ Implemented

- **Green / Q2a** — `SonarModel.predict_from_envelope`: envelope → 3-slice distances, vision-supervised.
- **Yellow / Q2b** — same training run yields the σ_sim-equipped forward path (`predict_from_profile`) used in the simulator.
- **Blue / Q2c with BC** — `EnvironmentSimulator` + pure-pursuit teacher → BC-trained RNN policy.
- **Mental-rep-as-teacher** — pure-pursuit policy along the arena's `target_path`.
- **M2 collapsed** — overhead Lorex + annotated arena, exogenous and pre-built.

### ❌ Not implemented (framework but not paper)

- **Q1 explicitly tested.** Sonar's preservation of distance is assumed, not measured.
- **Brooks-style direct action.** Policy consumes mid-continuum features (3-slice distances), not raw envelopes.
- **On-robot M2.** Vision here is external infrastructure, not an onboard learnable channel.
- **Multi-step continuum within M1.** One step shown (envelope → 3-slice); no further chain.
- **Bidirectional cross-modal.** M2 → M1 only; reverse not exercised.

### 🎚️ Why this specific cut

- **3-slice distance** as the M1 feature is one of many possible. Not claimed optimal. Chosen because *it was achievable* from 40 kHz-carrier envelopes.
- **Trained mapping carries (μ, σ²)** — the σ matters for the simulator (σ_sim) even though the policy currently runs `use_sigma=False`.
- **Cross-arena swap** is the primary control because it isolates "is F̂_M1 arena-specific?" from "is the policy any good in general?"

## 🏗️ Pipeline (concrete, from `rationale.md`)

### Stage 1 — Vision-coverage-driven acquisition

- `SCRIPT_BuildAcquisitionPlan.py` — samples random (x,y) waypoints inside arena polygon, respecting wall-clearance (250 mm) and feasibility.
- `SCRIPT_VisualDataAcquisition.py` — Lorex tracker drives robot through tour, pings at planned yaws.
- Output: `AcquisitionSessions/<session>/` with `(sonar_package, executed_pose)` per ping.
- **Why vision-driven** beats legacy IID-driven: gets uniform coverage including close-wall / corner configs that the legacy avoid-policy systematically skipped — and which are exactly where sonar errors are largest.
- **Framing for the paper:** *active cross-modal calibration* — vision both *supervises* and *gates exploration*.

### Stage 2 — Generic sonar model (green + yellow)

- `SCRIPT_TrainSonarModel.py`.
- One model trained on pooled data across sessions, held fixed across all downstream policy-training runs.
- Architecture `SonarSlicesUQ`: shared L/R encoder; centre head on (L+R)/2; side heads share weights with L/R swap.
- Loss: Gaussian NLL with log-σ² clamps; MSE warmup.
- Two callable interfaces from the same checkpoint:
  - **inverse path** (deploy): `predict_from_envelope` — real envelope → 6-key.
  - **forward path** (sim): `predict_from_profile` — geometric profile → 6-key with σ_sim noise.

### Stage 3 — Vicarious BC policy training (blue)

- `SCRIPT_TrainPolicy.py`.
- Per target arena, train one policy inside the simulator instantiated with that arena's geometry + target path.
- Teacher: pure pursuit (lookahead 200 mm), clamped to ±max_rotate_deg.
- BC with masked MSE + BPTT through full episode.
- **Three noise sources for sim→real robustness:**
  - Teacher perturbation (σ=30°, prob 0.30) — DAGGER-style recovery examples; label stays clean.
  - Per-step motor noise (3° rot, 5 mm drive) — zero-mean Gaussian.
  - Per-episode kinematic gain bias (`rot_gain ~ U(0.85, 1.15)`, `drive_gain ~ U(0.95, 1.05)`) — the *systematic* sim→real component. Forces the policy to use sonar feedback to compensate within an episode.
- Save: `PolicyTraining/<condition>/best_policy.json`.

### Stage 4 — Deployment + cross-arena swap

- `SCRIPT_RunPolicy.py`.
- Real robot in matched arena: real envelope → `predict_from_envelope` → 3-slice → RNN → rotation → drive.
- Logs everything per step (`sonar_package`, predictions, tracker pose, commanded actions, hidden state).
- **Primary experiment:** policy_A in arena_A vs policy_A in arena_B (and vice versa). Matched > swapped is the headline result.

## 🧪 Empirical structure

### Primary claim

> Matched policy outperforms cross-arena-swapped policy on path-following metrics in their target arena.

- If true: policies are arena-specific AND vicarious BC captures that specificity.
- If false (matched ≈ swapped): diagnostics — weak sonar model? insufficiently arena-specific teacher? BC instability?

### Secondary claim (blind ablation)

> A sighted policy outperforms a blind policy (sonar inputs stripped) on the matched arena, under motor-noise injection.

- Tests that the matched-condition success genuinely uses sonar feedback, not just dead-reckoning + memorised teacher field.
- The blind policy collapses to "what does prev_rot alone predict?" — should fail to compensate for the per-episode kinematic gain bias.

### Tertiary (already done, supports framework)

- σ calibration of the sonar model on held-out data (val-NLL).
- σ_sim fits per slice.
- L/C/R collapse check, overall-min comparison vs single-output baseline.

## 🌃 The "bat-flying-at-night" question

> Apparent weakness: paper requires a visual map of the *target* arena with no sonar measurements in it. When would a real bat have this?

Reframing for the discussion:

- The narrow claim ("bat has visual map but no sonar of this arena") is not the load-bearing one.
- **Broader claim:** if a bat ever has visual access to an environment, it can build F̂ and mentally rehearse sonar operation there — even later, in total darkness.
- Cases where this matters naturally:
  - Bat flies through a space at dusk (vision available) and later at night (vision gone).
  - Bat has familiarity with an environment from prior visits, even partially.
  - Bat uses other modalities (passive listening, airflow) to bootstrap F̂.
- **The point isn't biological realism in every detail** — it's that a generic vision→sonar transfer mechanism *exists* and is computationally tractable.

## 🚧 Open / to sharpen

- **Where do action and the Brooks-vs-deliberative split fit in the Q-hierarchy?** Currently the Action node sits outside Q1–Q2c. Worth deciding if "where you tap action on the representation continuum" deserves its own question.
- **Q1 caption sentence** — explicitly state that sonar/color is destroyed, sonar/distance is lossy, and that green/yellow only work in the lossy regime.
- **"Destroyed" vs "not in F_M" distinction** — conceptually different (filter actively collapses vs feature never reaches filter); worth a sentence somewhere.
- **Continuum step count in the M1 box** — paper has *one* learned step (envelope → 3-slice). Worth flagging that the framework supports more, and that future work could chain them.
- **`Estimated Sensory Data M1`'s dual role** — at training is the forward model's prediction-target; at vicarious deploy is the synthetic substitute for real data. Caption should disambiguate.
- **Bidirectional cross-modal** — currently only M2 → M1. A learnable M2 with feedback would let M1 supervise M2 too — interesting for the proposal, out of scope here.
